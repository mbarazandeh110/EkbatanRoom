# نقشه کلان معماری EkbatanRoom (System Blueprint)

پلتفرم EkbatanRoom از ۴ مخزن کاملاً مستقل تشکیل شده است که هرکدام مرز مسئولیت مشخصی دارند:

1. **`sfu-media-node` (Rust + mediasoup):**
   - مسئول پردازش سطح پایین رسانه (Router, WebRtcTransport, Producer, Consumer, RTP/RTCP).
   - کاملاً مستقل از پروتکل LiveKit و بدون ارتباط مستقیم سیگنالینگ با مرورگر.

2. **`signaling-coordinator` (Go Control Plane):**
   - مسئول اتصال وب‌سوکت، احراز هویت نشست (JWT)، مدیریت وضعیت اتاق‌ها (`RoomActor` و `ParticipantSession`) و هماهنگی با نود مدیا از طریق gRPC.
   - ارائه دو درگاه سیگنالینگ: `/rtc` (سازگار با کلاینت رسمی LiveKit) و `/ws/ortc` (پروتکل بومی).

3. **`rtc-compatibility-suite` (Black-Box Verification):**
   - مرجع مستقل تست سیاه‌جعبه با نسخه پین‌شده و بدون تغییر `livekit-client` برای سنجش ۵ دروازه فاز صفر.

4. **`web-client-pwa` (Next.js Frontend - این مخزن):**
   - فقط مسئول رابط کاربری، مدیریت وضعیت محلی (Zustand)، تعاملات اتاق، مدیریت دستگاه‌های ورودی/خروجی کاربر (دوربین/میکروفون/بلندگو) و نمایش وضعیت رسانه است.
   - هیچ منطق سرور سیگنالینگ یا پردازش سمت سرور رسانه نباید به این مخزن منتقل شود.
   - ارتباط با لایه رسانه منحصراً از طریق پورت انتزاعی `RtcEnginePort` انجام می‌شود تا سازگاری کامل با کلاینت رسمی LiveKit حفظ گردد.
