# مجموعه لود تست و سنجش کارایی سرتاسری (`loadtest-sfu`)

این مخزن پلتفرم ارکستراسیون و اجرای لود تست‌های مقیاس‌بالا و سرتاسری (E2E) برای پشته وب‌آرتی‌سی پروژه **EkbatanRoom** (ترکیب `signaling-coordinator` و `sfu-media-node`) مبتنی بر ابزار رسمی و آزموده‌شده **`livekit-cli` (`lk load-test`)** است.

---

## ۲. دروازه‌های تست مرحله‌ای (Sequential Gates)

کلیه آزمون‌ها با رعایت قاعده **Fail-Fast** به صورت ترتیبی اجرا می‌شوند؛ در صورت شکست هر گیت، گیت‌های سنگین‌تر بعدی اجرا نشده و به صورت `BLOCKED` ثبت می‌گردند:

| گیت | سناریو | ناشران | شنوندگان | کدک و رزولوشن | مدت‌زمان | هدف سناریو |
| :---: | :--- | :---: | :---: | :---: | :---: | :--- |
| **۱** | `gate-01-baseline` | ۱ | ۱۰ | VP8 (720p) + Opus | ۳۰ ثانیه | اعتبارسنجی اولیه پایداری، تبادل SDP و عبور روان مدیا |
| **۲** | `gate-02-broadcast` | ۱ | ۵۰ | VP8 (Simulcast) | ۱ دقیقه | ارزیابی توان Fan-Out و فیدبک‌های RTCP در پخش زنده |
| **۳** | `gate-03-group-conference` | ۱۰ | ۱۰ | VP8 (360p) Mesh | ۱ دقیقه | آزمون تعاملی دوطرفه و تلاقی بسته‌ها ($N \times (N-1)$ استریم) |
| **۴** | `gate-04-worker-spillover` | ۵ | ۱۵۰ | VP8 (720p) | ۲ دقیقه | اشباع ظرفیت ورکر اول و ارزیابی سرریز موفق به ورکر دوم |

## ۳. دستورات سریع و کاربردی

### ۳.۱ نصب و راه‌اندازی ابزار
```bash
# دانلود خودکار باینری رسمی lk در مسیر محلی bin/
make install-lk
```

### ۳.۲ اجرای تکی دروازه‌ها
```bash
# گیت ۱: آزمون پایه
make run-baseline

# گیت ۲: وبینار / برودکست
make run-broadcast

# گیت ۳: جلسه تعاملی گروهی
make run-conference

# گیت ۴: اشباع و سرریز ورکرها
make run-spillover
```

### ۳.۳ اجرای ترتیبی تمامی گیت‌ها (Full Suite)
```bash
make run-all
```

## ۴. تفکیک ریشه‌ای گلوگاه‌ها (Signaling vs Media Plane)

هنگامی که تست زیر بار دچار افت، تاخیر یا قطعی می‌شود:
1. **اگر در زمان ورود کلاینت‌ها (Join) یا برقراری وب‌سوکت تاخیر رخ دهد:**
   - گلوگاه در `signaling-coordinator` (صف پیام‌های Actor یا پردازش JSON/SDP) است.
2. **اگر بسته‌ها دور ریخته شده، فریم‌ها فریز شوند، یا مصرف CPU ورکر به بالای ۸۰٪ برسد:**
   - گلوگاه در ورکر مدیاسوپ `sfu-media-node` است و نیاز به سرریز ورکرها (Spillover) یا تنظیم بافرهای سوکت UDP دارد.
3. **گزارش‌دهی:** نیازمندی‌ها طبق قرارداد در `signaling-coordinator.requirements.txt` یا `sfu-media-node.requirements.txt` ثبت می‌گردند.

## ۵. شواهد و گزارش‌های آزمون

هر اجرای تست فایل شواهد ساختاریافته را در مسیر زیر ثبت می‌کند:
- `test-results/loadtest-report.json`: داده‌های ساختاریافته JSON برای اعتبارسنجی خودکار در خط لوله CI/CD.
- `test-results/<scenario>-run.log`: لاگ تفصیلی و خط‌به‌خط خروجی ابزار `livekit-cli`.
